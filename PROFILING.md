# Профилирование MeetRec

Замер 19 октября 2026 г., MeetRec 0.4.4, MacBook на Apple Silicon + внешний монитор 2560×1440. Способ тот
же, что у Genius Switcher и MXCtl: `scripts/profile.py` (память как в «Мониторинге системы»,
процессор, пробуждения; результаты в `scripts/profile-results.jsonl`), сборка `PROFILE=1
scripts/install.sh` (подпись с get-task-allow, чтобы подключались `leaks`, `heap`, `xctrace`) и
запуски с аргументами из `Profiling.swift`:

```bash
open -a ~/Applications/MeetRec.app --args --background --profile-recording 300  # запись 5 мин, файл в Корзину, без транскрибации
open -a ~/Applications/MeetRec.app --args --background --stress-test            # панель, выбор области, редактор ×3 круга
open -a ~/Applications/MeetRec.app --args --background --camera-test            # «Как я выгляжу» ×3 (камера включается)
xcrun xctrace record --template 'Time Profiler' --attach $(pgrep -x MeetRec) --time-limit 45s --output rec.trace
```

`--background` — чтобы панель не открылась при запуске: открытая панель меняет цифры.

## Итог

| | Память | Процессор | Пробуждения |
|---|---|---|---|
| **Покой** | 40–47 МБ | 0.1% | 0.1–0.6 в секунду |
| **Запись** 1440p HEVC, 15 к/с, оба звука, панель закрыта | 39–47 МБ, за 7 мин не растёт | **11–13%** одного ядра | ~0.5 в секунду |
| Запись, панель открыта | 41 МБ | 12.3% (было 18.8%) | |
| Сохранение после остановки (главы, смешанный звук) | пик 52 МБ (было +100 МБ на ~1 с) | 133% на 23 с у записи 1.5 ч | |
| Открытие панели | пик 43 МБ (было 143) | | |
| Стресс-тест (3 круга) | 107 → 59 → 62 МБ (было 173 → 198 → 155) | | |
| «Как я выгляжу» | MeetRec не меняется (40 МБ): камера в отдельном процессе `MeetRecMirror`, 200–350 МБ, пока окно открыто | | |

**Утечек нет.** `leaks` во время записи и после стресс-теста находит ~14 КБ внутренних объектов
системы (AppIntents, linkd) — столько же у Genius Switcher и MXCtl. Память во время записи ровная.

Куда уходит процессор во время записи (Time Profiler, панель закрыта): кодирование AAC двух
звуковых дорожек ~30%, приём кадров и звука от ScreenCaptureKit (распаковка буферов, в том числе
системой) ~30%, запись файла ~10%, видеокодер (аппаратный) ~4%, главный поток — остальное. Звук и
приём — работа системы, сократить их можно только качеством записи.

## Что исправлено

- **Закрытый редактор скриншотов держал картинку.** AppKit помнит последнее ключевое окно
  (`NSApp._previousKeyWindow`) и после закрытия, а через него — SwiftUI-вид, документ и картинку:
  ~14 МБ для скриншота 1440p плюс ~16 МБ буферов окна (для 5K в 4 раза больше). Теперь у закрытого
  окна убирается содержимое. То же для оверлея выбора области (держал замороженный экран) и окна
  «Как я выгляжу».
- **TIFF в буфере обмена сжимается (LZW).** Пока скриншот в буфере, MeetRec хранит его данные:
  было PNG + несжатый TIFF (14 МБ для 1440p), стало 2.5 МБ, +40 мс при копировании. После того как
  в буфер скопировано что-то другое, память возвращается (102 → 61 МБ).
- **Свободное место во время записи**: точное значение (`volumeAvailableCapacityForImportantUsage`,
  ~25 мс: macOS считает, что может очистить) — раз в минуту, между ним — дешёвый `statfs` и поправка
  на изменение. **Размер файла** — раз в 5 с (файл растёт фрагментами по 5 с; `stat` пишущегося
  файла ~2 мс). Тик записи стал ~в 3 раза дешевле.
- **Индикаторы уровня без анимации.** Анимация 0.15 с на каждое обновление (3 раза в секунду, два
  индикатора) перерисовывала всю панель с тенями на каждом кадре экрана: открытая во время записи
  панель стоила +5.7% ядра, теперь +1.2%. Масштабирование вместо ширины не помогло — дело в
  количестве кадров, а не в раскладке.
- **Статус кадра** читается через `NSArray`/`NSDictionary`, без копирования в словари Swift на
  каждый кадр.
- **«Как я выгляжу» брало OBS Virtual Camera**, когда встроенной камеры нет (крышка закрыта):
  выбор по умолчанию у macOS — виртуальная камера. Теперь сама выбирается встроенная, затем любая
  настоящая; виртуальная — только из меню. После закрытия у сессии убирается вход камеры.

## Второй заход (0.4.6)

- **Системные переключатели.** «Стеклянный» переключатель macOS 26 (`.toggleStyle(.switch)`) при
  первой отрисовке брал ~100 МБ графической памяти на долю секунды и оставлял ~6 МБ. На главной
  странице их два (микрофон, звук системы): отсюда пик 143 МБ при первом открытии панели и такой же
  после каждой остановки записи (панель возвращается к виду с переключателями). Теперь там свой
  переключатель, нарисованный SwiftUI (`LightSwitch.swift`), на вид такой же. Нашлось делением
  панели пополам: с пустой панелью пика нет, без блока источников нет, без любого одного ряда есть.
- **«Как я выгляжу» — отдельный процесс** `MeetRecMirror` (лежит в `Contents/MacOS`, запускается
  MeetRec и завершается с окном или с MeetRec). Камера держала 200–350 МБ, пока окно открыто, и
  ~70 МБ фрагментированной памяти в MeetRec после закрытия; теперь всё это уходит вместе с процессом.
  Разрешение на камеру — то же, что у MeetRec (процесс внутри его бандла).
- **Красная полоса на всю высоту экрана при остановке.** Индикатор «Сохраняю запись…» в кнопке без
  фиксированного размера на один кадр растягивал кнопку на всю высоту окна панели (оно прозрачное и
  доходит до низа экрана). Поймано видеозаписью экрана: ровно один кадр из ~400; с размером 16×16 —
  ни одного в трёх прогонах.

## Что осталось (не ошибки)

- Пик ~250 МБ, пока открыт редактор скриншота на весь экран (картинка и её отрисовка); после
  закрытия память возвращается.
- Пока скриншот лежит в буфере обмена, MeetRec хранит его PNG и сжатый TIFF (для 1440p ~6 МБ).
